parameters / temporary inference-time information

How can a model learn a new rule without changing its weights?

During training, a model develops parameters that determine how it processes information.

We can represent these learned parameters as:

θ — the trained machinery

But when a new problem arrives, θ does not necessarily need to be retrained.

A system can use information contained in the current input, previous context, or temporary internal state to behave differently for this particular problem.

Parameterswhat the machine learned during training
Temporary statewhat the machine currently knows or is computing

The important question is therefore not simply: “Did the model change?”

What changed—and where was that information stored?

Transformer, BDH, and HRM answer that question in very different ways.

Architecture Foundation

Three machines. Three computational organizations.

Three ways to organize reasoning

The same problem can be processed by very different computational structures.

TRANSFORMER

Attend

A Transformer processes representations using self-attention and feed-forward transformations.

Attention allows each position to dynamically determine which other positions are relevant to its current representation.

Route information according to relevance.
BDH

Interact

Dragon Hatchling organizes computation as a scale-free network of locally interacting neuron particles.

Instead of treating every component as globally connected in the same way, computation emerges through structured local interactions and dynamic synaptic state.

Let local interactions produce global computation.

BDH is described as an attention-based state-space sequence architecture with Hebbian synaptic working memory.

HRM

Coordinate

Hierarchical Reasoning Model contains two interdependent recurrent modules operating at different timescales.

H — high-level module
Slow, abstract planning.

L — low-level module
Fast, detailed computation.

Separate planning from execution while letting them communicate.

parameters / memory / workspace

What stays fixed? What persists? What is changing now?

Not everything inside a model serves the same role.

During inference, it is useful to distinguish three concepts.

PARAMETERS

What training built.

θ

Weights encode the computational transformations learned during training. For this chapter, imagine the trained parameters as the underlying machinery.

MEMORY

Information that remains available long enough to affect later computation.

Architectures implement memory differently. It may involve previously represented context, recurrent hidden state, or dynamic synaptic state.

WORKSPACE

The representation currently being transformed while solving the problem.

It is temporary and changes as computation proceeds.

These are conceptual roles, not universal components with identical names. A Transformer does not contain a literal box called Workspace. BDH and HRM do not store information in precisely the same way.

What stays fixed? What persists? What is currently changing?

How Does the Machine Remember?

Information can disappear—or remain useful

Suppose the machine is shown:

A → REDB → BLUEC → GREENB → ?BLUE

But the interesting question is not the answer. It is:

How was the information “B → BLUE” still available when it was needed?

The model's trained parameters do not need to be rewritten just to remember this particular example. Instead, each architecture has its own way of carrying information through the current computation.

TRANSFORMER

Keep the earlier context accessible

A Transformer can let the current representation retrieve information from earlier representations using attention.

B → ?attends back towardB → BLUE

In autoregressive Transformers, implementations often keep the already-computed keys and values of previous tokens in a KV cache. This avoids recomputing those earlier representations every time a new token is generated.

The context contains the information.
Attention retrieves from it.
The KV cache makes previously computed attention state reusable.

A KV cache is temporary inference state—not new knowledge written into the model's trained weights. This is more precise than saying simply “the Transformer remembers through the KV cache.”

BDH

Let recent experience alter temporary synaptic state

BDH uses a more explicit form of inference-time working memory. As information is processed, synaptic state can change through Hebbian-style plasticity.

B ─── BLUEafter associationB ═══ BLUE

The architecture has not permanently retrained itself. Information has been written into a dynamic synaptic working state that can influence later computation.

BDH can carry task information in changing synaptic state during inference.
HRM

Carry information through recurrent computation

HRM contains two interacting recurrent modules: H, a slower-changing higher-level state, and L, a faster-changing lower-level state.

H₀ → H₁ → H₂ → H₃L₀ → L₁ → L₂ → L₃ → …

Because these modules are recurrent, their current hidden states are passed forward into later computational steps.

HRM carries information through evolving recurrent hidden states.

That is not the same mechanism as BDH's dynamic synaptic working memory.

TRANSFORMERCONTEXTattention can retrieve from it
BDHSYNAPTIC STATEassociations can change
HRMRECURRENT STATEstate flows through time
All three can use information from earlier computation. What differs is where that information lives and how it is carried forward.

The Query Arrives

Suppose the system has already processed useful information about a task.

Then the actual query arrives:

◆ → ?

From the outside, Transformer, BDH, and HRM receive the same problem.

But once the input enters the model, the computational paths diverge.

The architecture determines:

  • how the query is represented,
  • what previous information it can interact with,
  • and what internal computation begins next.
TRANSFORMER

Build a representation, then relate it to context

The query is converted into an internal representation.

Inside Transformer layers, self-attention allows that representation to interact with other accessible representations, while feed-forward transformations continue modifying it.

Query representation↓Attention to relevant context↓Updated representation
The query joins a system in which relevance-based information routing is central.

The Transformer architecture is built from stacked attention and feed-forward sublayers.

BDH

Inject activity into an evolving network

In BDH, the query enters a network of locally interacting neuron particles.

The new input changes activity inside that network while interacting with its current state, including temporary synaptic structure built during previous processing.

The query therefore does not simply “look up an answer.”

It perturbs an already evolving computational system.

BDH is described as a scale-free graph of locally interacting units with inference-time synaptic working memory.

HRM

Initialize hierarchical reasoning

In HRM, the input is embedded into representations used by two interacting recurrent modules:

H — high-level state
L — low-level state

The query therefore enters a system where computation will unfold repeatedly between a slower high-level process and a faster low-level process.

Same query. Different machinery begins operating on it.

Where Does the Reasoning Happen?

The internal representations that are transformed between input and answer.

Between the query and the answer lies internal computation.

INPUT → ? → OUTPUT

The ? is where representations are transformed.

When we say a model is “reasoning internally,” we are referring to the computation occurring in those internal representations—not necessarily to a visible sentence such as:

“First I will do X, then Y.”
TRANSFORMER

Successive hidden representations

A Transformer repeatedly transforms representations through its layers.

X₀→X₁→X₂→…→Xₙ

Each layer combines attention with feed-forward transformation to produce updated hidden representations.

In an autoregressive language model, additional forward evaluations occur as new output tokens are generated.

Useful computation occurs inside changing hidden representations before we see the output.
BDH

Evolving network activity and state

BDH's computation is distributed across its network.

Sparse node activations, local interactions and dynamic synaptic state jointly influence what happens next.

The computation exists in the evolving network state.
HRM

Recurrent latent computation

HRM makes repeated internal computation especially explicit.

Its high-level and low-level modules recursively update their hidden states. The high-level module changes more slowly; the low-level module performs faster detailed computation.

These intermediate states do not have to be translated into a textual Chain-of-Thought.

Reasoning can occur as transformations of hidden state rather than as visible reasoning text.

How Does Information Move?

The communication topology of each architecture.

Imagine five pieces of information:

A   B   C   D   E

Suppose the information in A becomes important for processing E.

Different architectures provide different routes through which that influence can occur.

TRANSFORMER

Dynamic relevance routes

Self-attention computes relationships between representations.

A representation can assign greater influence to some accessible positions and less to others. So the effective routes depend on the current input.

The route is not simply “move one step to the neighbor.” It is formed according to attention relationships.

BDH

Local interaction builds longer-range influence

BDH starts from a different organization. Its neuron particles form a graph where individual units interact locally.

A → B → C → E

Because the graph has non-uniform connectivity, some nodes can also serve as highly connected hubs.

Global behavior can emerge from structured local communication.
HRM

Information moves across timescales

HRM's defining information flow is hierarchical.

Fast computation occurs inside the L module. Its evolving state interacts with the slower H module. The high-level state then influences later low-level computation.

Information moves not just across representations, but also between levels operating at different timescales.

From Internal State to Prediction

The distinction between internal representation and output representation.

The model's internal state is not yet the answer.

Inside the machine, information exists as numerical representations.

Those internal representations may encode everything required to solve the problem—but they still have to be converted into something the task expects.

a tokena class labela gridan action

This final conversion is performed through an output mapping/head/decoder, depending on the model and task.

TRANSFORMER

Language generation

For language generation, the current hidden representation is typically projected into scores over the vocabulary.

BDH

Internal state → task output

The evolving BDH representation similarly has to be mapped from the network's internal state into the output required by the task.

The important distinction is not a special “BDH decoder.”

network state ≠ observable answer
HRM

Output head

HRM's published sequence-to-sequence implementation includes an output head that transforms hidden states into token probability distributions.

Internal computation creates a representation. Decoding exposes a prediction.

How Deep Can the Machine Think?

How computation unfolds structurally before introducing deliberate test-time compute allocation.

Not every architecture obtains computational depth in the same way.

A computation can become deeper because information passes through more transformations, because a state is repeatedly updated, or because recurrent modules perform additional cycles.

TRANSFORMER

Depth through stacked transformations

Each block includes attention and feed-forward computation. For a fixed standard architecture, the layer stack provides a fixed amount of depth per forward evaluation.

BDH

Computation through evolving state

BDH combines its graph organization with state-space sequence processing, so its computation can be understood partly as an evolving system rather than only as one static graph evaluation.

HRM

Depth through hierarchical recurrence

The lower-level module performs rapid updates while the high-level module changes more slowly. HRM also includes adaptive computation time across computational segments.

Variable recurrent computational depth is explicit.
Important boundary

Architecture tells us what kinds of computation are possible inside the machine.

Another question remains: if extra inference compute is available, how should we allocate it? Save that for How Is Compute Spent?
